# Library API: before and after

The same small library API written twice. `before/` is legacy code with common .NET problems, on purpose. `after/` fixes each one. Read a row of the table, find the problem in `before/`, then see how `after/` handles it.

The layered version of this API, with separate domain, application and infrastructure projects, is in [trainning-api-csharp](https://github.com/FlipNeves/trainning-api-csharp).

## Running

Requires the [.NET 10 SDK](https://dotnet.microsoft.com/download).

```bash
dotnet run --project before   # http://localhost:5100/swagger
dotnet run --project after    # http://localhost:5200/swagger
```

Both start with the same three books in an in-memory database.

## What changed

| # | Problem in `before/` | Fix in `after/` | Why it matters |
|---|---|---|---|
| 1 | `.Result` on async calls (`GetBooks`, `LookupIsbn`) | `async`/`await` all the way, with `CancellationToken` | Each blocked request holds a thread. Under load the thread pool starves and the whole API slows down. |
| 2 | Errors answered with HTTP 200 and a `code` field in the body | Real status codes with `ProblemDetails` | Clients, proxies and monitoring read the status code. A 200 that means "not found" misleads all of them. |
| 3 | `throw ex;` in `UpdateBook` | No catch; the exception handler deals with it | `throw ex` resets the stack trace, so the log points to the wrong line. |
| 4 | `catch { return false; }` in `DeleteBook` | No catch; unexpected errors become a logged 500 | The caller can't tell "not found" from "database down", and nobody sees the error. |
| 5 | `new HttpClient()` on every lookup | Typed client from `IHttpClientFactory`, with base address and timeout | A new client per call can exhaust sockets and ignores DNS changes. Without a timeout, a slow server holds the request for 100 seconds. |
| 6 | Static state: `Startup.Configuration` and a `Dictionary` used as cache | Dependencies injected; `IMemoryCache` with expiration | The dictionary isn't thread-safe, never expires and grows forever. Static configuration hides dependencies and can't be replaced in tests. |
| 7 | `DbContext` created by hand in `BaseController` and never disposed | `DbContext` from dependency injection | DI creates one context per request and disposes it, and tests can swap the database. |
| 8 | Entity bound straight from the request body | Request and response records | A client can send `availableCopies` and the API saves it (over-posting). |
| 9 | `Id = Max(Id) + 1` | Key generated by the database | Two simultaneous requests get the same id. |
| 10 | Rules spread across controller `if`s | `Checkout()`, `Return()` and `Update()` on `Book` guard the rules | In `before/`, returning a book that was never lent pushes available copies above the total. |
| 11 | Availability stored as `Status = "A"` or `"U"` | `IsAvailable` computed from `AvailableCopies` | Stored derived state drifts: `before/` never sets `"A"` back on return. |
| 12 | ISBN checked by length only | ISBN-13 validated with its check digit | `9780000000000` is accepted by `before/`. |
| 13 | RPC routes (`/api/Book/GetBooks`, `/api/Book/SaveBook`) | Resource routes (`GET /books`, `POST /books/{id}/checkout`) | Verbs and status codes carry the meaning, and routes stay predictable. |
| 14 | Logs built with string interpolation | Message templates (`"Looking up ISBN {Isbn}"`) | Structured logs can be filtered by field. Interpolation flattens them into plain text. |
| 15 | Nullable reference types off, warnings ignored | Nullable on, warnings as errors | Building `before/` already warns about `throw ex` (CA2200), and nothing stops it. In `after/`, any warning fails the build. |

## Try it

- In `before/`, check out "Clean Architecture" (id 3, one copy), return it, and check it out again: it stays unavailable forever, because `Status` is still `"U"`. In `after/`, availability is computed, so this can't happen.
- In `before/`, `POST /api/Book/SaveBook` with `"totalCopies": 1, "availableCopies": 99` saves it as is. In `after/`, the request has no such field.
- In `before/`, `GET /api/Book/GetBook?id=999` answers 200 with an error inside. In `after/`, `GET /books/999` answers 404.
- In `before/`, return "Refactoring" (id 2) without checking it out: 4 of 3 copies become available. In `after/`, the same call answers 400.
